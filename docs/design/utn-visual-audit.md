# UTN visual audit

## Reference set

Reviewed all five supplied Windows screenshots at their native 1920×1080 resolution: `UTN-current-ui-01.png` through `UTN-current-ui-05.png`. They show the current application, not a proposed design. Screens 01–03 show Select in dark, light, and high-contrast themes; screens 04–05 show Pen in high-contrast and dark themes. The two Pen examples also expose different properties-panel widths and control arrangements.

## Findings grounded in the screenshots and implementation

| Area | What the screenshots show | Source evidence and effect |
| --- | --- | --- |
| Worksheet space | The canvas is clear and dominates the window, but the tool rail and properties area consume about 300–380 px before the page begins. | `ToolUtnContextBar::createItem` in `ToolUtnContextBar.cpp` fixes the side scroller at 208 px. It cannot be dragged narrower or wider. The gap is especially costly on a 1024 px classroom laptop. |
| Tool rail | The vertical rail is compact and the icon-only layout is useful; the active outline and nearby chevron make it visually busy. The rail itself scrolls in the shorter shots. | `#tbLeft1` gets repeated padding, radius and minimum-size overrides in `ui/xournalpp.css`; responsive labels are managed by `MainWindow::updateCompactLayout`. Toolbar item icons come from both legacy Xournal++ stock assets and newer UTN glyphs. |
| Inspector | Select in screenshots 01–03 leaves a largely empty dark/white panel after a short hint. Pen in 04–05 fills the panel with shape buttons, swatches, size presets, stroke and pressure. | `populate()` in `ToolUtnContextBar.cpp` gives each tool a different set of children in the same fixed-width scroller. Select and hand tools add a hint only. A fixed width does not respond to that difference. |
| Pen controls | Screenshot 04's black, outlined 2-column buttons are very large and waste vertical space; swatches, width presets and stroke controls have unrelated shapes. Screenshot 05's same controls are smaller and cleaner, but layout alignment still changes between groups. | `appendShapePicker`, `appendColourControls`, `appendSizeControls` and `appendPenControls` build independent grids and boxes. Side-panel size and swatch grids become three columns only in touch mode, so the ordinary panel uses long horizontal rows. |
| Icons | Main tool glyphs are mostly legible at the rail size. File actions and undo/redo in the app bar look like a mix of colorful legacy icons and outline GTK symbols, unlike the restrained teal tool selection. | `ToolMenuHandler` builds stock toolbar items and UTN custom items through different icon paths. `IconNameHelper.cpp` maps only some UTN names to theme icons. High-DPI and theme appearance therefore depend on the originating asset. |
| Buttons and alignment | Rounded selected tool buttons coexist with square shape buttons, pill swatches, linked size controls, a rounded badge and native comboboxes. The Pen title is a full-width white button in high contrast. Groups do not share a consistent left edge or spacing. | Styling is distributed across the base GTK theme, `UtnWidgets.cpp`, `ShapePicker.cpp` and successive CSS overrides in `xournalpp.css`. Individual widgets have local sizing and padding. |
| Text hierarchy | The tool names and helper copy are readable. Inspector sections such as Shape, Stroke, Size and Pressure do not form a consistent hierarchy, and the tool badge can resemble a primary action. | Only `.utn-context-title`, `.utn-context-hint` and `.utn-context-badge` establish shared text styles. Several other headings use unclassed labels. |
| Light theme | The white worksheet merges into the light inspector and toolbar because surfaces are similarly bright. Borders are visible but faint. Selected tool teal is clear. | The light chrome uses `#f7f8fb`, `#f5f7fa`, white and low-contrast `#dfe3e8` / `#e7e9ed` borders. The page canvas has its own rendering and should stay untouched. |
| Dark theme | Graphite rail and bars are coherent in 01 and 05, but the inspector is a single broad dark slab. Empty Select space makes the panel feel unfinished. Bright red/blue/green controls compete with the accent. | `.darkMode` changes only a few top-level surfaces and selected states. Context controls mostly inherit GTK theme styling. |
| High contrast | The pure black/white treatment and yellow selection are distinguishable in 03–04. Screenshot 04 makes every shape button a strong white outline, while the selected yellow panel and white swatches/chooser add competing emphasis. | `utnHighContrast` has broad button rules and later local overrides. High contrast needs state semantics preserved while removing duplicate visual emphasis. |
| Workspace and navigation | The lesson/document navigation sidebar is controlled independently at the canvas edge. It must remain independent from the tool inspector. | `panelMainContents` in `ui/main.glade` manages the document sidebar. The tool rail and inspector are `tbLeft1` and `tbLeft2`; they are siblings outside that paned. |
| Window sizes | The screenshots are 1920×1080 only. They do not prove behavior at 1024×768 or under Windows scaling. Fixed panel width and long tool labels are likely to squeeze the worksheet at smaller widths. | The code has compact rail labels below 1080 px, but the inspector has no user-resizable divider and its controls have fixed minimum widths. |

## Prioritised improvements

1. Put the contextual inspector and worksheet in their own horizontal `GtkPaned`, independent of `panelMainContents`. Add a keyboard-focusable divider, clamp it to the available window size, and persist the preferred width.
2. Add explicit “Hide settings”, “Show settings” and “Canvas only” controls. Keep the active tool and its state alive by changing widget parentage, not rebuilding toolbar items.
3. Reflow the side inspector at narrow widths, with visible scrolling if a control group cannot fit. Short tool configurations should stay compact rather than painting a large empty panel.
4. Give tool groups a shared surface, heading style, spacing scale, control height, selected treatment and focus ring. Preserve native high-contrast state distinctions.
5. Unify toolbar chrome and active/hover/focus states, then review the mixed legacy icon set. Replace assets only where an existing licensed project icon or GTK symbolic icon is available.
6. Offer Automatic / Show / Hide tool labels. Automatic should retain the current compact behavior; icon-only choices must retain accessible names and tooltips.
7. Verify light, dark and high-contrast modes at 1024×768, 1280×720 and 1920×1080, plus 100%, 150% and 200% Windows scaling. The supplied references do not cover those sizes or scaling levels.
