## Initial implementation plan

Goal: prevent whole-stroke erasing from deleting nearby ink because of a different segment's pressure width. Architecture: keep the existing circular distance test, broad-phase filtering, swept samples and undo ownership; use the renderer's outgoing-segment width. Tech stack: existing C++20, Cairo/GTK3, CMake, GoogleTest. Dedicated branch: `feature/utn-research-reliability`, based on verified PR #19 head `f802b7b28ab745a5f82885214cc34be64d28f9ec`.

Investigation ruling: an initial interpolation hypothesis was rejected after inspecting `StrokeViewHelper::drawWithPressure` and `StrokeContour`. Both use the starting point's width for each segment; the final point's pressure is not a drawable segment width. Highlighters use the fallback stroke width. The generic variable-width interval solver is therefore unsuitable for this handler fix. Kami K-ERASE-001 establishes only mode labels, not this algorithm; this is an independent UTN correctness correction.

Files: modify `src/core/control/tools/EraseHandler.cpp`; test `test/unit_tests/control/EraseHandlerTest.cpp`. No dependencies beyond existing test infrastructure. Do not alter `CircularEraser.h`'s separately documented generic geometry model.

Acceptance: eraser misses preserve the same stroke object and create no undo entry; true hits delete and undo/redo restore/remove correctly. Existing eraser tangency/sweep/persistence/export checks remain green. No per-pointer allocation added. Review focus: pressure decrease as well as increase; terminal pressure; highlighters; duplicate points; tangent/overlap hit and undo z-order. Existing single-point semantics are retained. Dashed gaps, filled interiors and partial eraser pixels are outside this correction.
